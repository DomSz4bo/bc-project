# Project Context

This project is a research prototype for a tool that incorporates software modelling (UML sequence diagrams specifically) into AI assisted software development. It uses AI agents and use feedback to iteratively refine software use cases via Sequence Diagrams before generating executable code.

## 🎯 Core Objectives
1.  **Visual Truth:** The Sequence Diagram (Mermaid.js) works as an additional source of truth. Logic must be verified visually before code is written.
2.  **Iterative Refinement:** The workflow is cyclical: *Discuss -> Visualize -> Critique -> Refine*.
3.  **Supervisor Orchestration:** A "Supervisor" agent manages the state and delegation between specialized sub-agents.

## 🤖 Agent Architecture (Supervisor Pattern)

The system uses the [subagents architecture](https://docs.langchain.com/oss/python/langchain/multi-agent/subagents) in LangChain/LangGraph where the central main agent coordinates the subagents. 

### 1. Supervisor Agent (central main agent)
* **Role:** Coordinator/Conversation holder.
* **Responsibility:** Talks to the user and orchestrates the subagents. Creates a plan that uses the subagents and presents the results to the user.
* **State:** Manages the global graph state.

### 2. Use case specialist
* Receives a system description and creates a Use Case from it.
* (or) Receives an existing Use Case and modifies it according to the given feedback.
* Use prompt techniques that support reasonig and deep thinking to achieve the best results possible. (Chain-of-thought, Step-by-step, Stop-and-think, etc.)

### 3. The Architect - subgraph
* Uses a [Evaluator-optimizer](https://docs.langchain.com/oss/python/langgraph/workflows-agents#evaluator-optimizer) workflow, having a **Modeller** and **Evaluator** node.

* The **Modeller**:
  * **Input**:
    * Use Case
    * Previous Sequence diagram (if exists)
    * Evaluation feedback (if exists)
    * Extra context if determined necessary by the supervisor.
  * **Work**: 
    * Analyzes the inputs and generates a Sequence diagram accordingly.  
    * Uses the "mermaid" tool to validate the diagram syntax.
  *  **Output**:
     *  A valid Sequence diagram in mermaid syntax.

* **Evaluator**:
  * **Input**: 
    * Use case
    * Sequence diagram
    * Extra quidance passed by the supervisor
  * **Work**: 
    * Analyzes the inputs and critiques the sequence diagram generated by the Modeller.
    * The diagram should be consistent with the Use Case and extra context
  * **Output**: 
    * Grade: pass or fail
    * Feedback: Provide a list of issues that make the diagram inconsistent with the inputs, with the purpose of guiding the modeller to a better result. (only if the grade is a fail) 


### 3. The Engineer - subgraph
* **Goal:** Implement the approved design.
* **Input:** A Use case and Mermaid Sequence diagram + Technical constraints.
* **Output:** 
  * Python or relevant implementation code.
* **Persona:** "Senior Backend Developer."

## 📝 Coding Standards

### Python & Chainlit
* **Async/Await:** Use `async def` for all Chainlit message handlers and LangGraph nodes to ensure non-blocking UI.
* **Type Safety:** Use `Pydantic` models for all structured outputs.
* **Chainlit UI:**
    * Use `cl.Message(content="...", elements=[...])` to send responses.
    * Wrap Mermaid code in triple backticks with the `mermaid` language tag:
        ```mermaid
        sequenceDiagram
            ...
        ```
